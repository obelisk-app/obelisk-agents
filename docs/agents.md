# Agents — LLM-connected bots

An **agent** is the second bot type in this repo. A classic bot is scripted
(price ticker, zap announcer); an agent is a group member whose replies come
from an LLM, and which **only hears whitelisted users** — everyone else is
invisible to it (they neither trigger replies nor enter the LLM context, so
the prompt-injection surface stays closed).

All runtime behavior lives in `lib/agent-bot.mjs`; a concrete agent under
`bots/` is a two-line entry point. Scaffold one with:

```bash
npm run new-bot -- helper --agent      # CLI
# or the "New bot → Agent" wizard on https://bots.obelisk.ar,
# which can also hand the description to Codex to refine it
```

## Configuration (env, prefix = bot name uppercased)

| Var | Meaning | Default |
|---|---|---|
| `<P>_NSEC` | identity | generated by the scaffold |
| `<P>_GROUPS` | `wss://relay\|groupId,…` | `BOT_GROUPS` |
| `<P>_RELAYS` | relays | `BOT_RELAYS` |
| `<P>_ALLOWED_PUBKEYS` | **whitelist** — npubs/hex allowed to talk to it | `AGENT_ALLOWED_PUBKEYS`; empty ⇒ deaf |
| `<P>_SYSTEM_PROMPT` | persona / instructions | generic helpful-member prompt |
| `<P>_TRIGGER` | `mention` (reply when mentioned / `@name`) or `all` | `mention` |
| `<P>_CONTEXT_SIZE` | messages of memory per group | 30 |
| `<P>_MIN_REPLY_GAP_MS` | per-group reply throttle | 4000 |

### LLM connection

| Var | Meaning |
|---|---|
| `<P>_LLM_PROVIDER` | `anthropic` or `openai` (auto-picked from which key exists) |
| `<P>_LLM_API_KEY` | key for that provider (or global `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`) |
| `<P>_LLM_MODEL` | default `claude-opus-5` (anthropic) / `gpt-4o-mini` (openai) |
| `<P>_LLM_BASE_URL` | openai-compatible endpoint override (OpenRouter, local llama.cpp, …) |
| `<P>_LLM_MAX_TOKENS` | reply budget, default 1000 |

Global fallbacks (`AGENT_LLM_*`) let every agent share one credential.
Anthropic uses the official `@anthropic-ai/sdk`; refusals
(`stop_reason: "refusal"`) are swallowed silently — the agent just doesn't
reply.

## Behavior

- Subscribes to kind 9 in each configured group (one filter per
  subscription, NIP-42 AUTH automatic).
- A message from a **whitelisted** pubkey is added to that group's rolling
  context (last `<P>_CONTEXT_SIZE` messages) and, if it mentions the agent
  (its npub, hex, or `@name` — or always, with `TRIGGER=all`), triggers an
  LLM completion posted as a kind-9 reply (`e`-tag to the trigger).
- Own messages and non-whitelisted users are ignored entirely.
- Replies are throttled per group and capped at 2000 chars.

## Security notes

- The whitelist is the only gate. Treat adding a pubkey as granting that
  person a direct line to your LLM budget.
- API keys live in `.env.local` like every other secret (the manager UI
  masks them; write-only).
- Agents publish only kind 9. Granting one admin powers (kind 9000+) is a
  human decision — see docs/admin-bot.md before doing that.

## Extending an agent

The stock runtime covers "chat member with a persona". For more (commands,
scraping/data sources on a timer, posting digests), extend the agent's own
`bots/<name>.mjs` next to `runAgent()` — reuse `lib/pool.mjs` and
`lib/state.mjs` per [building-bots.md](./building-bots.md). The Operator
(Codex) knows this layout and can do it from a description.
